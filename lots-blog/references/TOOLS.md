# LotsBlog launch tools

Use the live connection schema as the authority for fields and current availability.

- Blogs: `list_blogs`, `get_blog`, `create_blog`, `update_blog`. The private Markdown `blog_guide` is returned by get and editable through update; omit unchanged fields.
- Articles: `list_blog_posts`, `get_blog_post`, `create_blog_post`, `update_blog_post`, `delete_blog_post`, `restore_blog_post`. Create drafts by default; read back saved content. Set topic_ids from list_topics; omission preserves membership and [] clears it. Article writes return preview_url; drafts require authenticated access.
- Publication: `publish_post`, `schedule_post`, `unpublish_post`. Use only on the user's instruction. Scheduling requires a valid timestamp at least five minutes ahead and publishes on the next 15-minute check; returning to draft cancels the schedule. Public blogs ping IndexNow automatically when a post is published, edited or unpublished; there is nothing to call.
- Trash: `delete_blog_post` moves a post to Trash. It leaves the public site, sitemap, RSS and search at once, and nothing is deleted. `restore_blog_post` returns it to its previous status (a schedule that has passed comes back as a draft). `list_blog_posts` leaves Trash out unless you pass status `trashed`. Only the blog owner or an admin can delete a post forever, in the dashboard Trash. Owners and admins can trash any post; editors and authors their own.
- Cross-posts: set `canonical_url` on `create_blog_post`/`update_blog_post` to the original article's https URL. The post then names it as canonical and stays out of the sitemap and IndexNow. Another LotsBlog blog is refused; empty clears it.
- Topics: `list_topics`, `get_topic`, `create_topic`, `update_topic`, `delete_topic`.
- Images: `upload_blog_image` accepts a URL or small base64 image. For local files use `create_image_upload` → PUT bytes → `complete_image_upload`. `list_media` lists images and `delete_media` removes unused images on request.
- Domains: `connect_domain` returns required CNAME/optional TXT records. The user sets them; `check_domain` reports verification and HTTPS status. Both require blog-owner access.
- Subdirectory hosting: `connect_domain` with `domain` (such as example.com) and `path` (such as /blog) serves the blog at example.com/blog through one rewrite on the user's own site. It returns the proxy target, a private proxy secret and copy-ready rules for Cloudflare Workers, Vercel, Next.js, Netlify and Nginx. The rules never contain the secret: they read it from a Worker secret or environment variable named `LOTSBLOG_PROXY_SECRET` (Nginx: a separate include file), and each rule's `secret_storage` says where to put it. The user adds one rule; `check_domain` confirms it. Once verified, canonical URLs, the sitemap, RSS and llms.txt use example.com/blog and the lots.blog address redirects there. `get_blog` returns `subdirectory` (host, path, url, status, last check and error) to anyone with blog access, never the secret. `remove_subdirectory` (owner only, `confirm: true`) stops serving the blog at that path: canonical URLs return to the custom domain or lots.blog address; the user then removes the rewrite from their site. Treat the proxy secret like a password: give it only to the owner for their server-side settings, never in code, a committed file or public content.
- Article quality check: `run_post_quality_check`, a separate token-billed model task with explicit charge authorization.
- Results: `get_blog_analytics`, `get_post_analytics` report supported measurements, not rankings or conversions.

Appearance and team configuration remain available in the dashboard. Refresh/reconnect if your client has cached an older tool manifest without topic_ids or blog_guide. Do not invent missing tools. Keyword research, strategy, ideas, briefs and autonomous runtime are retained but outside launch discovery. Plans and purchased credits use the central billing catalogue; consult current pricing, never old example rates.
